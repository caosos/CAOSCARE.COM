## C. Strongest findings

1. **The echo/trust-boundary defect Lane A flagged as suspected (Room 121,
   2026-08-23) is now independently reproduced in Room 404 and confirmed by
   the resident's own words, not just inferred from timing.** Three
   fabricated "user" turns were persisted `trusted:true` in a 19-second
   window, one classified `coherent_barge_in` and two `no_overlap`.
2. **Two distinct, precise code-level causes, found by reading
   `frontend/src/lib/realtimeMessageHandler.js` directly (lines 43–58):**
   - `classifyUserTurn()` only reaches the echo-resemblance check
     (`resemblesAssistant`, line 53) when the turn is BOTH overlapped
     (`overlapped=true`, i.e. the mic segment started while
     `output_audio_buffer` was genuinely still playing) AND short (`isTiny`,
     `wordCount <= 2`, line 47). A turn that fails either condition — overlap
     happened but the phrase is 3+ words ("Of course, honey." — 3 words), or
     the phrase is short but arrives after playback has already stopped
     ("you need.", "Mine's all set now." — both `no_overlap` because
     `output_audio_buffer.stopped` had already fired) — **never reaches the
     resemblance check at all**, by construction (the `overlapped` early
     return at line 44, and the `isTiny` early return at lines 48–51).
   - This is a materially more precise statement than Lane A's Room 121
     finding ("delayed echo bypasses the trust boundary"): it is not one
     gap, it is two separate structural exemptions in the same function,
     and this session's cluster hit both of them back to back.
3. **Full-duplex mic capture is genuinely working at the transport level.**
   Multiple `speech_started` events fired with `assistant_speaking:true`
   while real playback was confirmed in progress (via the
   `output_audio_buffer`-driven flag, fixed 2026-08-22 per the file's own
   header comment — not the old broken `response.done`-based signal). The
   problem in this session is turn *classification*, not the mic pipeline
   failing to receive audio during playback.
4. **No listening-but-deaf dead zone occurred anywhere in this 8m11s,
   41-turn session**, despite running under the identical `interrupt_response:
   true` / `far_field` / `silence_duration_ms: 1000` configuration Lane A's
   regression matrix flagged as the leading deafness suspects. Every
   conversational pause (max ~15s) resolved normally.
5. **Operational truthfulness held throughout**, including two negative/
   honest-failure cases (transportation "requested" not "booked"; AC tool
   failure truthfully reported) and one duplicate-request case (truthfully
   said already on file, no fabricated new timestamp).
