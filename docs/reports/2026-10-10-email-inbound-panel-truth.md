# EmailInboundPanel loading/failure truth (da-61edb8f45c)

**Defect (reproduced at 20748cc by source and by the old panel failing all 8 new fixtures):** `load()` caught a failed `/email/allowlist` or `/email/inbound/messages` read with only a toast, while the initial empty arrays rendered "No approved senders - all email quarantined" and "No inbound email has been received." A 403 or outage therefore looked like a verified empty state; a failed refresh after a good load also left old data looking current; disabling a sender had no error handling.
**Fix (frontend only, no permission, policy or provider change):** each read has its own state: loading, error (never loaded), ok, or ok-but-stale (a later refresh failed). Empty statements appear only from a successful read, and say "as of the last successful load" when stale. Error and stale states have a Retry; overlapping loads and a closed panel are guarded (`latestOnly`); disable-sender failure shows the server's reason.
**Tests:** `emailInboundPanel.test.js`, 8 mounted-component fixtures (loading; allowlist 403 alone; messages alone; both; genuine empty; retry recovery; loaded then failed refresh; disable failure). Old panel fails all 8. Frontend 63 suites / 533 pass; `CI=true yarn build` compiled.
**Browser (isolated: scratch DB `rl_eip`, built UI served from a temp build, synthetic records, no provider; failures injected with DevTools request interception, GET only):** screenshots in `assets/2026-10-10-email-inbound/`: `1_loaded` (all statuses incl. "Needs a person - output could not be proven complete" with its reason, and "Processing"), `2_allowlist_403`, `3_messages_unavailable`, `4_both_fail`, `5_after_retry`, `6_stale_after_failed_refresh`. DOM checks for each case passed (error shown, no false empty claim, independent endpoints, retry recovers, stale banner with old data kept).
**Limits:** the 403/failures are injected, not produced by a real outage; no real mail; wording only checked in desktop width 1280; the stale timestamp uses the browser clock. Stack, build and scratch DB removed; Room 214 services, live page and backend untouched.
